# Prompt rendering spec (normative)

Kotlin `PromptBuilder` (`android/core`) and Python `ml/common/prompt_builder.py` MUST produce **byte-identical** strings from this spec. Golden files in `config/prompts/golden/` (generated by `ml/common/make_golden.py`) are checked by both test suites. PRD §13.3–§13.4 and Appendix C are the source; this file removes every ambiguity.

## 1. Files

| Task | System template | User template | Few-shots |
|---|---|---|---|
| `extract` (variant `base`) | `extract.system.txt` | `extract.user.txt` | `extract.fewshot.jsonl` (each line `{"user": "...", "assistant": "..."}`) |
| `extract` (variant `ft`) | `extract.system.ft.txt` | `extract.user.txt` | none |
| `patch` | `patch.system.txt` | `patch.user.txt` | none |
| `recommend` | `recommend.system.txt` | `recommend.user.txt` | none |
| `repair` | `repair.system.txt` | `repair.user.txt` | none |
| `warmup` | (no system message) | `warmup.user.txt` | none |

Template files are UTF-8, `\n` line endings. **Strip exactly one trailing `\n`** from every template after reading (files end with a newline). No other trimming.

## 2. Placeholder substitution

Plain text replacement of `{{name}}` (no logic, no escaping). Unknown placeholders are an error.

| Placeholder | Value |
|---|---|
| `{{category_list}}` | One line per category in `taxonomy.json` order: `CODE: definition` joined with `\n`. |
| `{{severity_rubric}}` | Lines `CRITICAL: …`, `HIGH: …`, `MEDIUM: …`, `LOW: …` (this order) from `severity_rubric`, joined with `\n`. |
| `{{field_catalogue}}` | One line per category except `OTHER`, taxonomy order: `CODE: f1, f2, …` (fields in taxonomy order). `EQUIPMENT` line is `EQUIPMENT (also fill equipment): …`. Field rendering: enum → `key(V1\|V2\|…)` using `\|`-free plain `|` separators, i.e. `fire_status(ACTIVE|CONTAINED|EXTINGUISHED|SMOKE_ONLY|UNKNOWN)`; `string` → `key:text`; `string_list` → `key:list of text`; `bool` → `key:true/false`; `int` → `key:number`. |
| `{{tool_schema_fill_incident_form}}`, `{{tool_schema_update_incident_fields}}`, `{{tool_schema_propose_actions}}`, `{{tool_schema}}` | Compact JSON of `config/schemas/tool_<name>.json`: keys in file order, separators `,` and `:` (no spaces), non-ASCII kept as-is. |
| `{{transcript}}`, `{{answer}}`, `{{broken}}` | The text as given (caller strips leading/trailing whitespace). |
| `{{asked_field_specs}}` | One line per asked field: same rendering as the field catalogue (`key(A|B)`, `key:text`, …); `occurred_at` renders as `time:text (time phrase as spoken)`; common fields use their taxonomy definition. Joined with `\n`. |
| `{{asked_fields}}` | Asked keys joined with `, ` (`occurred_at` written as `time`). |
| `{{question_text}}` | The spoken question (English or Hinglish). |
| `{{form_compact_json}}` | Compact JSON object of **satisfied** fields only (status ≠ MISSING; UNKNOWN fields as `"UNKNOWN"` for enums, omitted for others). Key order: common fields in taxonomy order, then `"details"` (object, category fields in taxonomy order) if non-empty. `occurred_at` is written as `"time": <expression>` (the spoken phrase, or `"now (assumed)"` when DEFAULTED). `lang`, `title` omitted. |
| `{{actions_taken_list}}` | Compact JSON array of strings (`[]` if none). |
| `{{sop_candidates}}` | Lines `ID: text` joined with `\n`. |
| `{{tool_name}}` | Tool name string. |

## 3. Chat assembly (Llama 3.2, no BOS)

```
S(role, text) = "<|start_header_id|>" + role + "<|end_header_id|>\n\n" + text + "<|eot_id|>"
prompt = [S("system", system)]  (omitted for warmup)
       + for each few-shot: S("user", fs.user) + S("assistant", fs.assistant)
       + S("user", user)
       + "<|start_header_id|>assistant<|end_header_id|>\n\n"
```
No `<|begin_of_text|>` (Genie adds BOS; PRD §13.9). No newline between `<|eot_id|>` and the next header.

## 4. Golden cases (`config/prompts/golden/`)

| File | Inputs |
|---|---|
| `extract_slide.txt` | extract/base, transcript = `There was a water leak near Conference Room 2 around 10 AM. Maintenance has already isolated the area.` |
| `extract_slide_ft.txt` | extract/ft, same transcript |
| `patch_slide.txt` | patch; form = slide extraction result (type WATER, description, location, time "around 10 AM", actions_taken); asked = `injuries, severity`; question = `Was anyone hurt, and how serious is the situation right now?`; answer = `No one is hurt, it's minor.` |
| `recommend_slide.txt` | recommend; same form plus injuries NO, severity LOW, leak_source "burst pipe under the sink", leak_status STOPPED; candidates = SOP P0 candidate list for that form |
| `warmup.txt` | warmup |

`make_golden.py` writes these; the Kotlin test renders the same inputs and compares bytes.
