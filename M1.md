# IncidentVoice — M1 Approach Summary

**Megathon X × Qualcomm · Problem Statement 1: AI Incident Report Assistant**
Voice in → structured incident report out. Everything runs **on the Qualcomm QIDK (Snapdragon 8 Elite, Hexagon NPU V79), offline, no cloud.**

## 1. What we are building

A worker taps the mic and describes an incident in **English or Hinglish** ("Block B ke store room mein ek ladka seedhi se gir gaya…"). The device transcribes it, understands it, fills a structured report, **asks by voice only for what is missing**, suggests next steps from site SOPs, lets the user review, and stores the report in a searchable on-device dashboard. Critical incidents (fire, unconscious person, gas leak) trigger an **instant emergency banner** with one-tap dial.

```
SPEAK ─► UNDERSTAND ─► EXTRACT ─► VALIDATE ─► ASK (voice) ─► RECOMMEND ─► REVIEW ─► SUBMIT ─► DASHBOARD
 mic +    Whisper-small  Llama 3.2 3B   rule-based   TTS + auto-mic   SOP library   editable   SQLite    search,
 VAD      (on-device)    on Hexagon NPU validator    ≤3 rounds                      form       + FTS     filters
                          tool call
```

## 2. Pipeline

| Stage | How | Where it runs |
|---|---|---|
| Capture | Tap-to-talk, Silero VAD auto-stop after 1.2 s silence, noise suppression, ≤30 s | CPU |
| Speech-to-text | Whisper-small (multilingual) — whisper.cpp now, NPU via ONNX Runtime-QNN as upgrade | CPU → NPU |
| Understand + extract | **One** Llama 3.2 3B Instruct call (w4a16, Genie runtime) emits a JSON **function call** `fill_incident_form{…}`: classifies the incident, translates Hinglish to English, fills common + category fields | **Hexagon NPU** |
| Validate | Deterministic rules from a taxonomy config: which fields are mandatory for this category | CPU (no model) |
| Ask | Templated questions in the user's language (EN / Hinglish), ≤2 related fields per question, ≤3 rounds; answer → `update_incident_fields{…}` patch call | TTS on CPU, LLM on NPU |
| Recommend | Category SOP checklist (vetted steps), shown on the review screen; LLM tailoring as upgrade | CPU / NPU |
| Review + submit | Editable form, required fields highlighted, "Unknown" allowed | App |
| Store + dashboard | Room (SQLite) + full-text search; recency list, keyword search, category/severity filters | App |

## 3. Incident model

- **10 general categories + Other:** Fire, Medical/Injury, Water leak, Electrical, Gas/Chemical (Hazmat), Equipment failure, Security, Structural/Facility, Environmental, Vehicle. One primary + up to 2 secondary types.
- **Common fields (every report):** type, description, location (fuzzy-matched to a site registry), date/time (spoken phrases like "around 10 AM", "aadha ghanta pehle" resolved deterministically; defaults to now if not said), severity (Low/Medium/High/Critical with a rubric + safety rules), injuries, persons, equipment, actions taken, witnesses, near-miss flag.
- **Category fields:** 2–3 mandatory per category (e.g. Fire: fire status, evacuation, fire brigade called) plus optional detail fields.
- **Function calling:** the LLM only *extracts*; the app owns a registry of functions (`fill_incident_form`, `update_incident_fields`, `ask_followup`, `submit_incident_report`, `trigger_emergency_banner`) and executes them. Output is schema-validated, enum-normalised and grounded against the transcript (no invented names).

## 4. On-device AI on Snapdragon

| Model | Format | Expected speed on 8 Elite |
|---|---|---|
| Llama 3.2 3B Instruct | AI Hub Genie bundle, w4a16, HTP V79 | ~28 tok/s decode, ~730 tok/s prefill (AI Hub, Galaxy S25 = same SoC) |
| Whisper-small | whisper.cpp (CPU) → AI Hub QNN binaries (NPU) | NPU: ~66 ms encoder, ~8 ms/token decoder |

Engineering rules from prior QIDK work: one NPU session at a time, models kept resident, greedy decoding for extraction, no double BOS token, hardware errors retried (3/7/15 s) and never shown as "AI refused". **Target: ≤ 8 s from end of speech to a filled form**, with fields appearing as they stream.

## 5. Why this meets the judging criteria

| Criterion | Evidence |
|---|---|
| On-device, Snapdragon acceleration, no cloud | LLM on Hexagon NPU; app has no internet permission; demo in airplane mode; debug overlay shows NPU timings |
| Natural conversational speech | Hinglish + English, filler words, self-corrections, relative times |
| ASR accuracy | WER (English) / CER (Hinglish) on 30 recorded clips from the hall |
| Extraction accuracy | Incident-type accuracy + per-field F1 on ~150 template-generated text cases |
| Correct field mapping | Separate mapping-accuracy metric; strict schema + rule validator |

## 6. Plan and status (as of M1)

- **Team:** two tracks — **ML/NPU** (model export, inference engine, prompts, validator, evaluation) and **App** (Android UI, audio, TTS, database, dashboard).
- **Done:** full PRD, board set up (clock fixed, 29 GB freed), QAIRT 2.50 runtime downloading, **Llama 3.2 3B V79 export running** on two machines in parallel.
- **Next (M2):** first end-to-end run on the board: speech → transcript → tool-call JSON → validated form.
- **Risks & fallbacks:** export delay → Llama 3.2 1B → CPU llama.cpp; NPU Whisper → whisper.cpp on CPU; app can't reach NPU → shell-user inference service (Plan B).

## 7. Beyond the MVP (future slide)
